# 固定动作问题核查记录

核查日期为 2026年10月5日。用户反馈不同问题总得到“淘宝新客投入增加 10%”。线上浏览器已复现：选择利润优先并输入抖音获客成本上升、流量下降和竞品降价，动作仍是淘宝拉新；解释来源为模板，语义调用返回 RateLimitError。

## 已确认的原因

旧策略在原环境的 98 次独立决策中全部选择淘宝拉新。旧测试报告中的训练后平均 Reward 为 0.08663880598214285，随机初始化为 0.13221535348214286。旧模型的训练效果没有支持其统一建议。

旧环境中的渠道效率固定；输入状态缺少淘宝等渠道的 ROI/CAC；随机初始化指标、外部信号缺失模式与 CSV 输入不同。共同状态价值和较小动作差异混在单一输出网络中，训练容易形成动作偏好。

文本中的库存、CAC 定性描述被保留为证据，按原设计不覆盖数据库中的实测指标；部分外部信号可以进入状态。前台没有充分说明这一边界。经营目标原先依赖下拉框，修改文本并不会改变默认目标。

实际 API 检查返回 HTTP 429 和 credit_balance_exhausted。现在公开安全的错误类别，短期停止重复调用，并明确标记规则解析和模板解释。密钥和供应商响应体不输出到页面或日志。OpenAI 官方说明见 https://developers.openai.com/api/docs/guides/error-codes 。API 余额未恢复，本次没有声称 LLM 已成功调用。

## 本次修改

补充 10 项渠道指标，状态变为 40 因子、40 存在标记、12 目标权重，共 92 维；7 项收益和 5 项惩罚的计算定义没有改变。

使用 Dueling Q 网络区分共同状态价值和动作优势。冷启动数据为 210 种合成经营状态，每种配合 7 个目标；合法动作共享随机扰动，单期终止 SARSA 的目标只使用实际仿真 Reward。随后继续多期 SARSA 更新，目标仍使用实际 A′ 的 Q 值；没有用 max Q 代替，也没有用规则或 LLM 强行替换已选动作。

训练随机化渠道投入、效率、库存、价格、成本及外部信号缺失模式。已有活动周期保留原模型完成学习，结束后升级；原模型归档，已有经营数据和历史保留。

增加根据文本识别经营目标的选项；用户仍可手动选择。明确表达的预算上限、禁止增加渠道投入及禁止新增促销进入动作约束。无关问题返回提示，不创建营销动作。结果显示问题、目标、实际预算或价格影响、Q 值差距和回退原因。文字描述不伪装成实测数据。

## 独立测试

固定共同种子 12000–12015，每种策略 16 轮、每轮 14 天，共 224 次决策。旧模型读取同一状态中其原有的 30 个因子、对应存在标记和目标权重。

| 指标 | 旧模型 | 本次模型 |
|---|---:|---:|
| 最常选择动作的占比 | 95.09% | 42.86% |
| 不同动作数 | 3 | 8 |
| 平均综合 Reward | 0.168708696875 | 0.168552390268 |

两者平均 Reward 接近，本次结果未显示稳定的回报优势，不能据此声称提高企业利润。测试数据和训练数据都是合成数据。详细计数保存在 data/policy_audit.json；共同测试比较结果保存在 data/experiments.json。没有伪造 LLM-only 或 LLM+SARSA 的实验结果。
