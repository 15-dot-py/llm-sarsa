# 新数据驱动决策与产品对照

调研日期：2026-10-06。比较公开可核实的代表性产品及官方文档，未登录付费产品开展全功能测试；这不是“全网所有网站”排名。

## 为什么要改

原系统有 CSV 上传入口，但采用整批替换、至少 10 行的方式。用户需要补充一个渠道或一个新观察日时很难操作。数据库刷新也缺少明确的完成状态；输入文字不会直接改写实测库存或获客成本，用户因此容易以为模型一直使用旧数据。

本次把“更新观测”与“提交已执行动作的结果”明确区分。手工录入和 CSV 均按 `(date, channel)` 更新，同键修正、新键追加。最新状态由观察日期决定，修正旧日期不会把观察日倒退；不过修正历史收入可能改变趋势和波动指标。

## 产品对照与采用的做法

| 产品 | 已核实的能力 | 对本项目的启发及采用情况 |
| --- | --- | --- |
| [Metabase](https://www.metabase.com/docs/latest/exploration-and-organization/uploads) | CSV 上传可创建、追加或替换表；追加需要列结构匹配，系统不替用户识别重复行 | 已实现增量上传及保存前预览。本项目另外按日期与渠道去重更新，避免同日重复计入收入 |
| [NocoDB](https://nocodb.com/docs/interfaces/layouts/table) | 表格展示、行内编辑及记录详情 | 已在现有数据表增加“编辑”和“新增记录”，用一个记录表单录入，沿用原深色工作台 |
| [Langfuse](https://langfuse.com/docs/evaluation/experiments/datasets) | 数据集条目的增删改产生版本，可指定版本运行实验 | 已记录数据版本、内容哈希及更新来源，建议保存对应的观测快照。尚未实现任意历史原始数据集重建、版本回滚及完整 Langfuse 实验平台 |
| [Google Meridian](https://developers.google.com/meridian/docs/basics/meridian-introduction) / [GitHub](https://github.com/google/meridian) | 用营销组合模型估计渠道影响并给出预算优化报告；[优化器](https://developers.google.com/meridian/reference/api/meridian/analysis/optimizer/BudgetOptimizer.md)支持预算、分配和投入约束 | 对照后保留预算与毛利约束、来源和模型边界。它可作为后续归因/预算优化基线；本次未把 MMM 冒称为 SARSA，也未额外接入 Meridian |
| [Albert](https://albert.ai/ai-marketing-software/) | 产品方称其可分析人群和投放数据，跨搜索、社交与程序化渠道分配预算、调整活动 | 提醒本项目重点是运营数据与执行结果联动。这些是厂商功能声明，未据此认定其效果优于本项目；本项目仍由用户确认实际执行，不自动修改真实投放账户 |

判断：这些产品在数据操作、观测追踪或营销预算规划方面各有可借鉴之处。尚没有证据证明本项目综合性能更优。竞赛中宜用独立测试场景和明确的基线验证优势，避免用页面效果、模型名称或厂商宣传替代业绩证据。

## 页面怎么操作

1. 点工作台右上角“更新数据”，或侧栏“运营数据库”。当前观察日和数据版本显示在工作台上。
2. 少量更新用“新增记录”或表格中的“编辑”；批量更新用“导入增量 CSV”。最少 1 行，最大 2 MB、合并后最多 9,000 行。CSV 用 UTF-8 或 GBK；空白模板使用 UTF-8 BOM，避免 Excel 中文乱码。
3. 默认演示工作区勾选“合成 / 测试数据”。导入真实观测须取消该选项。首次真实导入移出合成原始样例；已有实际反馈的观察日保留。已有真实观测的工作区禁止混入测试上传。
4. 预览新增、修正和数值相同的行数，以及保存前后的最新观察日、收入、贡献利润、ROI。仔细核对后点“确认保存更新”。预览有效期 10 分钟；预览后若工作区发生变化，须重新预览。
5. 回工作台新建决策。建议使用更新后的当前观测，决策记录写入数据版本、内容哈希及观测日。相同模型、状态和约束仍可能得到相同动作，这本身不代表未读取新数据。

最新日期只提供一个渠道时，该日汇总只代表已提供的渠道，其他渠道不会从旧日补齐。完整的多渠道比较应先导入当日各渠道观测。未提供成本会明确提示估算；CSV 可选成本列整列空白会被忽略，部分空白须补全或移除该列。年报、研究报告、未来预测不可直接冒充真实日级运营记录。

## 当前已有决策时

| 当前状态 | 数据更新行为 |
| --- | --- |
| 无活动决策 | 更新观测，模型权重不变，下一次建议读取新状态 |
| 首轮草稿未执行 | 保存更新后取消旧草稿并保留记录，再生成新建议 |
| 动作已确认执行 | 须将新增一个后续观察日明确选作本轮经营反馈；不能跳过结果直接替换当前状态。跨多个新日期的上传须先完成本周期 |
| 上一轮等待下一实际动作 | 先确认下一实际动作，或在工作台结束周期；不能在等待期间改写 SARSA 的下一状态 |

已执行动作提交渠道级观测后，系统计算实际结果的 Reward，建立转移；非终止周期仍须确认下一实际动作 A′ 后，使用 `Q(S′, A′)` 更新。勾选结束周期则按终止转移更新。测试上传生成的反馈标记为测试，不能视为企业业绩。首次真实数据不能与初始合成状态直接组成实际训练转移。

仅上传观测不代表执行了投放，不触发学习；历史数据修正也不会撤销已经发生的模型更新。旧决策及其结果保留原有快照，校正数据须建立新版本；更新日志不是模型回滚工具。

## 外部数据接入

已提供工作区级接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/data/preview` | JSON 提交渠道记录、来源和说明，返回预览令牌 |
| `POST /api/data/preview-upload` | Multipart 上传 CSV；来源为 `uploaded`、`manual`、`demo_upload` |
| `POST /api/data/apply` | 使用预览令牌保存，支持明确将新日观测作为反馈 |
| `GET /api/data` | 读取当前原始记录、日指标、版本日志和模型输入 |
| `GET /api/data/template.csv` | 下载空白运营模板 |

读写接口沿用现有工作区鉴权。连接淘宝、抖音或企业内部库，需要数据所有者提供授权接口和字段映射。目前没有企业授权数据源，因此本次实现的是可用的录入、增量导入和接入接口，未宣称自动获得三只松鼠内部订单。

## 保存与验证

数据写入服务端工作区，并进入现有签名浏览器恢复备份。Render 免费实例的本地数据库仍不是永久云存储；同一浏览器可尝试恢复，换手机需导入恢复备份。重要记录请在决策记录中导出完整工作区。没有开启收费持久磁盘或新增付费数据库。

回归测试覆盖新观测进入决策状态、历史修正不倒退日期、单行去重更新、草稿快照保留、预览冲突、重复保存、实际反馈与 A′、成本缺失、渠道缺失和签名恢复。具体发布及公网结果见 `artifacts/data-update-live-check.json`。
